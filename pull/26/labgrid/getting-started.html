Getting started

This page shows the smallest useful local workflow.

The goal is simple. Run one hardware test from your shell and see that hw-test can acquire a board through labgrid.

Before starting, you need:

  • a labgrid coordinator address,

  • at least one exporter connected to that coordinator,

  • a labgrid place with tags matching the test you want to run,

  • an envs/<place>.yaml file for that place,

  • SSH access to the exporter user used by the env file.

Start from a checkout of hw-test:

python3 -m venv .venv
source .venv/bin/activate
pip3 install --upgrade pip
pip3 install -e '.[test]'

This creates a Python environment and installs hw-test in editable mode.

Next, tell labgrid where the coordinator is:

export LG_COORDINATOR=<coordinator>

Run one small test first:

set='{"name": "adsp/smoke"}' pytest tests/adsp/smoke/test.py -vvv

The set variable is the test context override. The most important field is name. It must match the test directory under tests/.

For example:

set='{"name": "adsp/u-boot"}' pytest tests/adsp/u-boot/test.py -vvv

This tells hw-test to build the context for tests/adsp/u-boot and run that test.

Some tests have their own Python requirements. Install them before running the test:

pip3 install -r tests/adsp/u-boot/requirements.txt
set='{"name": "adsp/u-boot"}' pytest tests/adsp/u-boot/test.py -vvv

If a test downloads artifacts from GitHub Actions, set GITHUB_TOKEN and pass the workflow run URL:

export GITHUB_TOKEN=<token>

set='{
  "name": "adsp/bootstrap",
  "workflow_run_url": "https://api.github.com/repos/example/project/actions/runs/123"
}' pytest tests/adsp/bootstrap/test.py -vvs

Or provide local built artifacts at the expected path; the log guides you through the necessary setup:

$

set='{"name": "adsp/bootstrap"}' pytest tests/adsp/bootstrap/test.py -s

   Neither 'workflow_run_url' in context or 'GITHUB_REPOSITORY' in environment,
   cannot download artifacts; assuming you have them at
   '/hw-test/_artifacts/adsp/bootstrap/0'

$

cp /path/to/my.dtb /hw-test/_artifacts/adsp/bootstrap/0/my.dtb

$

set='{"name": "adsp/bootstrap"}' pytest tests/adsp/bootstrap/test.py -s

 [...] SUCCESS

When you are still bringing up a setup, avoid running all tests:

pytest tests

That will try to acquire every matching board and run all hardware tests. Start with one test, one place, and one board.

If the local run fails, check these first:

  • LG_COORDINATOR points to the right coordinator.

  • labgrid-client places shows the expected place.

  • labgrid-client -p <place> show shows the expected matches and tags.

  • The test’s needs list matches the place tags.

  • envs/<place>.yaml exists.

  • SSH to the exporter works for the NetworkService user.
