Client Usage

A client is a developer shell, CI job, or test process that uses labgrid to lock a place and drive the board. This page assumes the board is already registered. To add a new board, see Register Your Device.

For the first local run, virtualenv setup, LG_COORDINATOR, and basic pytest commands, start with Getting started. This page only covers reusable client code and CI integration.

For labgrid command details, use the upstream labgrid documentation.

Useful labgrid inspection commands:

labgrid-client places
labgrid-client resources
labgrid-client who
labgrid-client -p <place> show

Writing Tests

Tests should use hw_tests.labgrid.LabgridClient instead of open-coding labgrid session handling. It selects a matching place from needs, acquires it, configures SSH, and releases it at the end.

Small smoke test:

from hw_tests.labgrid import LabgridClient


def test_smoke(context):
    client = LabgridClient(context)
    with client.acquire() as target:
        ssh = target.get_driver("SSHDriver")
        ssh.run_check("true")

U-Boot style test:

from hw_tests.github import GitHub
from hw_tests.labgrid import LabgridClient


def test_uboot_version(context):
    github = GitHub(context)
    images = github.download("adi_sc598_ezkit_defconfig-bootstrap")

    spl = images / "u-boot-spl"
    uboot_image = images / "u-boot"

    client = LabgridClient(context)
    with client.acquire() as target:
        spi_boot = target.get_driver("DigitalOutputProtocol", name="spi_boot")
        power = target.get_driver("PowerProtocol")
        ssh = target.get_driver("SSHDriver")
        openocd = target.get_driver("OpenOCDDriver", activate=False)
        uboot = target.get_driver("UBootDriver", name="uboot", activate=False)

        spi_boot.set(False)
        power.cycle()
        ssh.put(str(spl), "u-boot-spl")
        ssh.put(str(uboot_image), "u-boot")
        spi_boot.set(True)

        target.activate(openocd)
        try:
            openocd.execute(openocd.load_commands)
        finally:
            target.deactivate(openocd)

        target.activate(uboot)
        uboot.console.sendline("version")
        uboot.console.expect("U-Boot", timeout=30)

The important pattern is:

  • get drivers by protocol when possible, for example DigitalOutputProtocol,

  • copy images to the exporter before OpenOCD needs them,

  • activate drivers only when they are needed,

  • release the place by leaving the with client.acquire() block.

Test Context

Each test has a config.toml. The needs list selects compatible places:

needs = ["adsp", "sc598"]

The local command-line form for set, GITHUB_TOKEN, and workflow_run_url is shown in Getting started.

CI Usage

In GitHub Actions, the workflow needs access to GitHub artifacts and to OPKSSH identity tokens:

permissions:
  actions: read
  contents: read
  id-token: write

jobs:
  hardware-test:
    runs-on: ubuntu-latest
    env:
      LG_COORDINATOR: ${{ secrets.LG_COORDINATOR }}
    steps:
      - uses: actions/checkout@v6
      - name: Run U-Boot test
        uses: ./run-test
        with:
          set: >
            {
              "name": "adsp/u-boot"
            }

id-token: write is needed only when exporter SSH access uses OPKSSH. Without it, opkssh login github cannot get a GitHub OIDC token.
