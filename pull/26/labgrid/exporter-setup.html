Exporter setup

An exporter is the machine connected to the hardware. It owns the USB serial adapters, debug probes, power controllers, GPIO lines, and files staged for OpenOCD or U-Boot. The coordinator tracks those resources, but the exporter is the host that can physically access them.

This page only covers exporter host setup. To add a board after the exporter is running, see Register Your Device.

For the complete labgrid exporter syntax, use the upstream Exporter Configuration reference.

Install packages

Install Python, SSH, serial tools, udev, and the tools needed by your debug stack. Use the OpenOCD package from the system if it supports the board. Build a custom OpenOCD only when the board support is not available in the package.

$

sudo apt-get update

$

sudo apt-get install -y \
 git python3 python3-venv python3-pip \
 firewalld microcom ser2net udev

If OpenOCD must be built locally:

$

sudo apt-get install -y \
 autoconf automake libtool pkg-config \
 libjim-dev gcc g++ make texinfo gdb-multiarch \
 libusb-1.0-0-dev

$

sudo dnf install -y \
 git python3 python3-pip \
 firewalld minicom ser2net systemd-udev

If OpenOCD must be built locally:

$

sudo dnf install -y \
 autoconf automake libtool pkgconfig \
 jimtcl-devel gcc gcc-c++ make texinfo gdb \
 libusb1-devel

$

sudo zypper install -y \
 git python3 python3-pip \
 firewalld microcom ser2net udev

If OpenOCD must be built locally:

$

sudo zypper install -y \
 autoconf automake libtool pkg-config \
 jimtcl-devel gcc gcc-c++ make texinfo gdb \
 libusb-1_0-devel

Users and permissions

Use two Unix users:

labgrid

Owns labgrid-exporter as a systemd user service.

labgrid-client

Acts like an “SSH jump host”, is used by clients and tests to reach the target.

Both users need access to serial ports, GPIO devices, USB debug probes, and the labgrid cache directory.

$

for group in users dialout uucp labgrid plugdev gpio; do

 getent group "$group" >/dev/null || sudo groupadd --system "$group"

done



$

sudo useradd --create-home --home-dir /home/labgrid \
 --shell /bin/bash --gid labgrid \
 --groups users,dialout,uucp,labgrid,plugdev,gpio labgrid



$

sudo useradd --create-home --user-group --shell /bin/bash \
 --groups users,dialout,uucp,labgrid,plugdev,gpio labgrid-client

If the users already exist, update their groups:

$

sudo usermod -aG users,dialout,uucp,labgrid,plugdev,gpio labgrid

$

sudo usermod -aG users,dialout,uucp,labgrid,plugdev,gpio labgrid-client

Terminate the labgrid user to refresh group memberships, and enable linger so the exporter service can start at boot.

$

sudo loginctl terminate-user labgrid

$

sudo loginctl enable-linger labgrid

Check real device permissions before debugging labgrid:

$

readlink -f /dev/serial/by-id/<your-device>

$

ls -l /dev/ttyUSB0

$

id labgrid-client

$

sudo -u labgrid-client test -r /dev/ttyUSB0 && echo client-can-read

$

sudo -u labgrid-client test -w /dev/ttyUSB0 && echo client-can-write

For USB debug probes, install udev rules from OpenOCD or add a local rule for the probe vendor and product ID:

ATTRS{idVendor}=="1234", ATTRS{idProduct}=="5678", MODE="660", GROUP="plugdev", TAG+="uaccess"

Then reload udev:

$

sudo udevadm control --reload-rules

$

sudo udevadm trigger

Directories

Create the directories used by labgrid and by file staging:

$

sudo -iu labgrid

$

mkdir -p ~/.config/labgrid

$

mkdir -p ~/.config/systemd/user

$

mkdir -p ~/.local/bin

$

mkdir -p ~/.local/share/venvs

$

exit

$

sudo install -d -o root -g labgrid -m 2775 /var/cache/labgrid

/var/cache/labgrid must be writable by the labgrid group. File upload, OpenOCD, scp, and image staging can fail if this directory is missing or too strict.

Install labgrid

Install labgrid in a venv owned by the labgrid user:

$

sudo -iu labgrid

$

git clone https://github.com/labgrid-project/labgrid.git ~/labgrid

$

python3 -m venv ~/.local/share/venvs/labgrid

$

~/.local/share/venvs/labgrid/bin/pip3 install --upgrade pip

$

~/.local/share/venvs/labgrid/bin/pip3 install --upgrade ~/labgrid

$

exit

Expose the commands:

$

sudo -iu labgrid

$

ln -sfn ~/.local/share/venvs/labgrid/bin/labgrid-client \
 ~/.local/bin/labgrid-client

$

ln -sfn ~/.local/share/venvs/labgrid/bin/labgrid-exporter \
 ~/.local/bin/labgrid-exporter

$

~/.local/bin/labgrid-client --help >/dev/null

$

~/.local/bin/labgrid-exporter --help >/dev/null

$

exit

SSH and OPKSSH

hw-test needs SSH to the exporter because tests copy files and run commands on the exporter. For local development, normal SSH keys are enough:

$

ssh-copy-id labgrid-client@lab-exporter-01

$

ssh labgrid-client@lab-exporter-01 true

In GitHub Actions, hw-test uses OPKSSH. The test helper downloads opkssh if needed, runs opkssh login github, writes an _ssh_config file, and checks SSH access before running the test. The workflow job must have:

permissions:
  id-token: write
  contents: read
  actions: read

The exporter SSH server must trust the OPKSSH identity used by your organization or repository. Keep that server-side policy in the lab infrastructure; hw-test only performs the client login and SSH check.

Exporter Service

Create an empty exporter config file and use the service file shipped by labgrid as the base:

$

sudo -iu labgrid

$

touch ~/.config/labgrid/exporter.yaml

$

install -m 0644 \
 ~/labgrid/contrib/systemd/labgrid-exporter.service \
 ~/.config/systemd/user/labgrid-exporter.service

$

exit

Edit the copied service file. At least set LG_COORDINATOR to your labgrid coordinator:

[Unit]
Description=Labgrid Exporter
After=network-online.target
Wants=network-online.target
StartLimitIntervalSec=0

[Service]
Environment="LG_COORDINATOR=labgrid-coordinator.example.com"
EnvironmentFile=-/etc/environment
ExecStart=%h/.local/bin/labgrid-exporter -d --hostname lab-exporter-01 %h/.config/labgrid/exporter.yaml
Restart=always
RestartSec=30
User=labgrid
Group=labgrid
SupplementaryGroups=dialout plugdev gpio

[Install]
WantedBy=default.target

Enable the service:

$

sudo systemctl --user --machine=labgrid@.host daemon-reload

$

sudo systemctl --user --machine=labgrid@.host enable --now labgrid-exporter.service

Open the console proxy port range:

$

sudo systemctl enable --now firewalld

$

sudo firewall-cmd --permanent --add-port=30000-59999/tcp

$

sudo firewall-cmd --reload

Check the service:

$

sudo systemctl --user --machine=labgrid@.host status labgrid-exporter.service

If the service starts, the exporter host is ready. The next step is to register a board in Register Your Device.
